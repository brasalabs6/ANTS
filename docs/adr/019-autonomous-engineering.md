# ADR-019 — Delegated autonomous engineering

Status: accepted by maintainer delegation, 2026-11-26. Supersedes IC v1.0's mandatory external reviewer and per-item maintainer approvals for development work only. See [IC v1.1](../25-implementation-contract.md).

Context: R01 passed tests and CI but an unavailable external reviewer stopped all dependent implementation. The maintainer delegated autonomous implementation, technical decisions, review, integration and continuation of the existing R01–R09 roadmap. The R01 exception was recorded before merge in [PR #1](https://github.com/brasalabs6/ANTS/pull/1#issuecomment-7204161168).

Decision: standing development authorization; no per-item human approval, no required human reviewer for development integration. Use independent automated review when available, always record actual reviewer identity and mode, resolve material findings, run reproducible positive/negative acceptance and quality gates on exact candidate, verify remote checks/HEAD and rerun affected checks after merge. If an external reviewer is unavailable, documented author-side technical review plus executable evidence is accepted for development integration under this policy; never claim it independent. Security-sensitive development slices additionally require explicit threat model and negative/adversarial tests. Missing mandatory evidence or failed checks cannot be converted into PASS; block only affected work and proceed with unrelated authorized work. Keep exceptions explicit and narrowly scoped.

Development scope: existing roadmap, source, tests, documentation, isolated synthetic environments, issues/PRs and non-destructive merges. No standing authority for new credentials, paid services, real customer/production data, releases, destructive infrastructure changes, privilege changes, bypass of platform confirmations or real unattended external effects. Runtime operator controls and independent product evidence review are unchanged. Do not redefine runtime authorization to make development easier. Revert development integration with reviewed/tested fix or revert commit, not history rewrite. Maintain durable handoff and resumable ownership.

Consequences: progress no longer relies on maintainer availability for normal coding or merge decisions. Automated verification is not equivalent to independent security assurance. Release/production gates remain separate; external access and actual tool availability may still block particular tasks. No claim of continuous execution absent an active scheduler.
