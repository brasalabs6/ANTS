# 19 — Guardrails and human approvals

Status: v0.7 proposed normative MVP requirement, extends 06, 14, 17, 18. Human control is enforced by the application and execution boundary, not by prompts or UI.

## Policy

Versioned constitution and guardrail policy, scoped by organization/colony/goal/runner. Effective policy is the intersection of hard platform limits and applicable operator-approved policies; child cannot widen parent. Deterministic decisions: allow, require_approval, deny. Deny overrides allow; approval cannot override deny. Default deny unclassified external effects, unknown capabilities and unenforceable managed actions. Explicitly authorize ordinary read/work/checkpoint actions within scope; separate plan acceptance, artifact review, goal completion and external side-effect authorization. Examples for benign software projects: read approved workspace, write isolated branch, run local tests within resource limits; approval for publishing a release, deleting data, changing production, increasing budget or external sharing; deny access to unrelated workspaces/secrets. Never embed unrestricted execution presets. Operator changes are authenticated, audited, revisioned; changing policy invalidates incompatible outstanding requests/tokens and rechecks pending runs. Agents may request changes, not grant them.

## Approval contract

Approval request: org_id, colony_id, goal/task/run IDs and revisions, actor/session, request ID, policy revision/hash, action kind, canonical parameters hash, target/environment, scope, rationale, risk/impact, estimated cost, evidence refs, created/expires, status pending/approved/rejected/expired/revoked/consumed, decision principal/time/reason, version. Server generates from structured intent after policy evaluation; not arbitrary command from board. UI displays exact action, relevant diff and uncertainty; reject or request revision with reason. Only authorized human principal may approve human-gated request; cannot self-approve as agent. No blanket reusable approval; scoped to specific action hash and target, single use, short TTL. Approval is not execution success. Rejection blocks that intent; alternate safe work may continue. No retries to pressure operator or split action to evade approval. Expiry defaults to no execution. A changed action requires new request.

Atomic consume: authenticate runner/action caller; lock applicable scope and budget state in [22](22-execution-contracts.md) canonical order; recheck active revision, scope, deadline, approval hash, expiry, revocation, lease/fence, budget and policy decision; consume approval and persist idempotent execution intent; commit. Enforced gateway/sandbox performs only bound action with scoped capability, checks current revocation before execution. Reconcile uncertain external effect; do not blindly retry. Pause/cancel/revoke prevents new authorization, invalidates unused grants and pending run intents; already performed effects cannot be undone automatically. Revocation race with external execution documented and minimized.

## Policy evaluation and stop semantics

Evaluate hard deny and scope first; then required approval; then allow. If multiple applicable policies disagree, most restrictive wins (deny > require_approval > allow); missing necessary scope or unclassified controlled action is deny. No human approval overrides hard platform deny. Distinguish approval of plan strategy, independent review of artifact, criterion verification and controlled action grant; one is not automatically the other. A pending/rejected action blocks that exact intent while independent authorized work proceeds. A colony-wide pause blocks all affected claims/dispatch and invalidates grants, persisted across restart. Resume requires operator and fresh authority; no automatic restart after cancellation. Track effect status separately from decision and disclose uncertain external outcome. Scope approval to immutable action hash, policy/goal/task/run revision and expiry; changes require new request. Keep audit reason, actor, old/new revision. See [22](22-execution-contracts.md).

## Integration boundaries

Managed runner must route controlled effects through enforcement boundary and sandbox; deny if enforcement unavailable. BYO agents with direct shell/network access cannot be fully controlled by ANTS; enforce ANTS API and controlled integrations, display external execution limitations, do not claim that dashboard guardrails constrain an arbitrary remote agent's machine. Recommend explicit isolated workspaces and scoped credentials. No secret access or permission expansion through message board. Human approval UI is not a substitute for provider/platform security policies.

## API/CLI (draft)

Versioned colony routes for policy read/propose/apply, approval list/detail/decision, approval revocation, goal/colony pause and run cancellation. Commands: ants guardrails show; ants guardrails set --file policy.toml; ants approvals list --json; ants approvals show ID; ants approvals approve ID --reason TEXT; ants approvals reject ID --reason TEXT; ants run cancel ID. Operator scope required for decisions. Expected version, idempotency key and reason for consequential commands. Agent context includes pending approval IDs, safe remaining work and reason; no credentials. Events: approval.requested/approved/rejected/expired/revoked/consumed; policy.updated/denied; run.cancel_requested. SSE uses scoped events. No frontend direct DB or authority decisions.

## Tests

Default deny and intersection precedence; approval cannot override deny; stale policy/goal/task/action hash rejected; cross-tenant access denied; expired or reused grant rejected; concurrent consumption one winner; pause race, revoke race, budget reservation and idempotency; untrusted post cannot issue grant; rejection leads to blocked intent without retry spam; approved action executes exactly its authorized scope in mock gateway; report external outcome separately; dashboard/CLI parity, keyboard accessible decisions, reconnect and audit. Test with synthetic benign workload and mock actions. Gate real runner use and public alpha on verified controls. Research metrics: operator interventions, approval burden, false blocks, prevented unauthorized actions, completion quality and recovery; transfer findings to Plane after independent validation.
