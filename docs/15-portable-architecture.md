# 15 — Portable architecture and revised implementation sequence

Active v0.7 portable deployment specification. [02 architecture](02-architecture.md) is the matching modular overview; [12 canonical roadmap](12-roadmap.md) owns milestone details. Historical stack choices are in Git and [21](21-project-context.md).

## Structure

apps/ants: one distributable executable with separate client, host and runner composition roots; apps/web: Vite operator dashboard required for public alpha, optional at runtime; packages/domain, application (including deterministic Goal Engine use cases), contracts, storage-sqlite, storage-postgres (later), transport-http, cli, runner, pulse, sdk (later), mcp (later), telemetry. Keep TypeScript strict. Runtime Bun, workspace pnpm or Bun (choose one lockfile in scaffold; pnpm baseline retained until spike). Application ports for transactional store, clock, artifacts, credentials, runner, events. No business logic duplicated between adapters. CLI client and optional MCP adapter use the same versioned colony service contract. Joining a served colony is a client operation only; it never starts a server or opens a database. Keep client dependencies on contracts/transport, not storage internals. Server alone owns its authoritative state while serving. Runner connects as an independently authenticated client, optionally on a different host. See [client/server and research strategy](16-colony-client-and-research.md).

Local state under explicit --data-dir or .ants/: constitution.md (exported/readable copy), colony.db, config.toml, artifacts/; DB authoritative constitution revision/hash, file updates only via authorized import command. Restrictive permissions, credentials separate. Migrations transactional where supported. WAL and foreign_keys on; busy timeout; use BEGIN IMMEDIATE for state mutations, short transactions, no LLM/network inside. SQLite database on local disk only; one server owns writes in remote mode, other clients use HTTP. For local one-shot commands use same transaction and process coordination; avoid conflicting service migrations. Backup via SQLite backup API or quiesced snapshot including artifacts, never copy live DB alone. Export versioned manifest with checksums; import validates paths and scopes, never auto-enables runners.

Cloud adapter retains organization/colony tenant isolation, RLS and Postgres fences/outbox design. Local schema also carries org/colony IDs; local single-operator mode is not a substitute for hosted auth. SQLite lease correctness tested separately: conditional update inside serialized write transaction instead of SKIP LOCKED. FTS5 baseline with capability check and bounded lexical fallback. No Redis, broker or embedding service required. HTTP versioned JSON and scoped SSE for the operator dashboard. UI optional during operation, required for public alpha. Vite assets may be embedded later if packaging spike proves reliable.

## Delivery sequence

See [12 — Canonical roadmap](12-roadmap.md) for the sole active R01–R09 backlog and exit criteria. R01 validates compile and local storage; R02 lifecycle; R03 client join/roles/board/context; R04 plan/intent/task/evidence; R05 recovery; R06 Goal Engine/mock Pulse/approvals; R07 operational dashboard and public alpha; R08 hosted SaaS; R09 research transfer. This is a dependency sequence, not delivered functionality. Keep Vite assets optional at runtime; use embedded assets if verified, separate static bundle fallback. No mandatory cloud service. See [23 requirements](23-requirements.md).

## Release acceptance

Clean machine with binary only, no Bun/Node/Postgres/Docker/MCP; local init, constitution, goal, remote/local join, board, plans/intents, role-aware claims, checkpoint, replacement, verification, mock Pulse, approvals, pause, export/import. R07 also requires functional Command Center and browser-independent runtime. Test actual target binaries on OS matrix; document external agent runtime prerequisites separately. Measure installation friction, time to first verified contribution, recovery quality, duplicate work and cost. Do not promise zero context loss or unsupported platform compatibility.
