## Implementation checklist (6 items)

- [ ] **R05.01 — Export and import**
  - Implementation: Versioned scoped manifest with schema version, DB/objects hashes, metadata and format compatibility; operator authorization, bounded extraction, no secrets or automatic runner activation. Import into explicit new dir or approved restore, validate before publish.
  - Acceptance: Round trip preserves goals/events/evidence/lineage; malicious paths, invalid hashes and unknown version rejected; runners disabled.

- [ ] **R05.02 — Consistent backups**
  - Implementation: SQLite backup API or quiesced snapshot including referenced artifacts, manifest and retention, restricted permissions; document restore and encryption limitations. Never copy live DB alone or WAL over network FS.
  - Acceptance: Concurrent write backup restores consistent DB/artifact refs; integrity_check and hashes pass; missing object reported.

- [ ] **R05.03 — Crash recovery**
  - Implementation: Restart migrations safely, recover outbox/consumer receipts, expired fences, incomplete uploads and interrupted transitions; persist pause/revocation; no assumption exactly-once external effects.
  - Acceptance: Fault injection before/after commit and restart yields coherent state; no work after persisted stop.

- [ ] **R05.04 — Session reconciliation**
  - Implementation: Detect stale sessions/leases/attempts, reconcile actual managed status where known, close or mark uncertain, preserve checkpoint and request authorized replacement through future Pulse. External process liveness not guaranteed.
  - Acceptance: Killed session recovered without inherited credentials; uncertain effects not blindly replayed; false online status avoided.

- [ ] **R05.05 — Concurrency and security tests**
  - Implementation: Run SQLite multi-connection/process contention, DAG/claim/idempotency, scope, lease expiry and stop races; create deterministic fault fixtures and migration tests, track actual durations/limitations.
  - Acceptance: Repeatable automated matrix demonstrates no duplicate effective claim, cross-scope data or stale mutation; failures documented.

- [ ] **R05.06 — Distribution and checksums**
  - Implementation: Build release candidates for tested OS/arch, SHA256 manifest, signing procedure/verification, versioned upgrade and backup instructions; probe embedding UI and fallback. No publication until R07 gate.
  - Acceptance: Clean host smoke and checksum verification; tampered binary fails verification; unsupported targets explicitly marked.

## Milestone exit gate
Restore from consistent exported data on clean host; tamper and crash recovery tests pass, no runners auto-enabled, verified binary checksums.
