## Implementation checklist (13 items)

- [ ] **R06.01 — Goal reconciliation**
  - Implementation: Deterministic engine consumes durable triggers and checks current goal/constitution/policy, criterion evidence, limits and runnable work; persist evaluation intent, dedup/fence and next check atomically. No LLM supervisor.
  - Acceptance: Replay/restart yields one effective request; no success when queue empty; succeeded/paused goal stops dispatch.

- [ ] **R06.02 — Missing criteria detection**
  - Implementation: Evaluate required criteria against approved consistent candidate hash/rules, classify unknown/fail/stale, track meaningful progress and blockers; independent review/human gate as configured.
  - Acceptance: Green unrelated test, self-attestation, stale or tampered fixture cannot satisfy criterion; all approved checks pass before terminal success.

- [ ] **R06.03 — Proactive planning**
  - Implementation: Request role-specific bounded gap analysis on activation, missing coverage, failed verification or stagnation; planner proposals flow through R04 admission, coalesce bursts/cooldown and dedup work. Missing eligible planner visible.
  - Acceptance: Empty queue with unmet criterion triggers new planning without human continuation; replaced planner resumes; no retry spin.

- [ ] **R06.04 — Event-driven scheduler**
  - Implementation: Pulse disabled by default; operator enables explicit event/interval/manual trigger policy, durable RunIntent, dedup, next eligible time, bounded retries/backoff/deadline. Dispatch outside transaction after authority recheck.
  - Acceptance: Fake-clock trigger dedup, disabled restart, cooldown and expiry tests; no worker = waiting blocker.

- [ ] **R06.05 — Runner and role matching**
  - Implementation: Register fixed authorized adapter/argv template, workspace, allowed environment/capabilities/role/concurrency; separate RunAttempt and Session, fenced claim and heartbeat. No arbitrary shell interpolation or auto-register.
  - Acceptance: Ineligible role/runner denied; remote polling remains supported; revoked runner cannot dispatch; no unrestricted provider execution.

- [ ] **R06.06 — Mock Planner**
  - Implementation: Deterministic fixture planner reads context and proposes plan/intents/tasks tied to unmet criteria; no direct DB privilege, role scoped CLI/API. Generate revised plan after controlled failure.
  - Acceptance: Mock reproducible output, concurrent stale proposal rejected; fresh planner can resume; no model API key.

- [ ] **R06.07 — Mock Worker**
  - Implementation: Deterministic mock claims, renews, publishes checkpoint and immutable fixture result through public contract; simulate controlled failure/termination, safe limited workspace.
  - Acceptance: Two mock workers run independent tasks, kill one and recover with new fence; no stale write or external action.

- [ ] **R06.08 — Mock Reviewer**
  - Implementation: Different authenticated principal reads approved fixture/verifier, submits evidence/verdict with candidate hash; fail first candidate then pass repaired candidate.
  - Acceptance: Independent review enforced; edited acceptance test or stale candidate rejected; reviewer cannot self-approve.

- [ ] **R06.09 — Budget and concurrency**
  - Implementation: Atomic reserve/settle integer micro-units + currency, org/goal cap and per-run max duration, active session limit, deadline, attempt/no-progress limits. Unknown managed cost fail closed under hard cap; BYO cost unknown labeled.
  - Acceptance: Parallel final reservation one winner, release/settlement idempotent, exhaustion halts dispatch; no negative balance or hidden cost claims.

- [ ] **R06.10 — Policy Engine**
  - Implementation: Deterministic scope intersection deny>ask>allow, default deny unknown controlled effects, revisioned policies and structured ActionIntent; managed mock gateway enforces action not prompt. Distinguish plan/review/approval.
  - Acceptance: Table tests for precedence, stale revisions, untrusted board text and scope expansion; deny cannot be overridden by approval.

- [ ] **R06.11 — Human Approval Inbox**
  - Implementation: Persist exact action hash/target, policy/goal/task/run revision, expiry, requester, rationale and evidence; authorized human approve/reject/revoke via CLI/API and initial UI. Single-use atomic consume, separate effect status.
  - Acceptance: Expired/changed/reused/cross-scope approvals denied; concurrent consume one winner; rejection blocks only affected intent.

- [ ] **R06.12 — Revocation and cancellation**
  - Implementation: Serialize pause/cancel/revoke with claims, reservations, evaluations and dispatch; invalidate leases/grants, stop managed mock process safely, reconcile uncertain effects. Human resume fresh authority; external BYO compute limitation explicit.
  - Acceptance: Race tests no new authorization after stop commit; restart preserves stop; independent allowed work continues after action-specific rejection.

- [ ] **R06.13 — Autonomous pursuit tests**
  - Implementation: End-to-end deterministic scenario activate once → plan → parallel work → replace sessions → failed verifier → replan → repair → final verification; approval allow/deny, no-progress and budget/deadline variants. Record evidence and research baseline.
  - Acceptance: Success only on verified criteria, no further human continue prompts, stop after terminal state; blocked/exhausted honest outcomes.

## Milestone exit gate
Activate once, planning/work/failed verification/replan/verified success across worker replacement using deterministic mock runners; approval denial and stop races pass. Real unattended providers explicitly excluded until PR-25 security gate.
