## Implementation checklist (12 items)

- [ ] **R04.01 — Versioned Plans**
  - Implementation: Implement PlanRevision, rationale, criterion coverage, alternatives, author and current pointer, proposed/accepted/rejected/superseded states; fenced planning lease or CAS admission; operator gate configurable. Changes invalidate affected work only.
  - Acceptance: Concurrent admission one winner, stale revision rejected, alternative retained and unaffected task continues.

- [ ] **R04.02 — Exploration Intents**
  - Implementation: ExplorationIntent question/hypothesis, goal/plan/parent revision, expected evidence, cap, dedup, states and supported/refuted/inconclusive/converted outcomes. Distinct from RunIntent/ActionIntent. Allow direct tasks and worker proposals.
  - Acceptance: Reject cross-goal/cyclic/unbounded lineage; refuted intent retained with evidence, never implies goal success.

- [ ] **R04.03 — Dependency graph**
  - Implementation: Persist task revision dependencies scoped to same goal/mission and accepted prerequisite revision; serialized edge writes, DAG cycle check and blocked reason projection. No graph DB.
  - Acceptance: Concurrent edges forming cycle rejected; upstream invalidation marks dependent work stale; ready query respects DAG.

- [ ] **R04.04 — Task lifecycle**
  - Implementation: Implement proposed→ready→leased→in_review→done, release/reject/expire→ready, authorized cancel/reopen via revision. Typed tasks reference goal revision and criterion/supporting purpose, optional plan/intent.
  - Acceptance: Invalid transitions and direct Done bypass denied; cancelled filter and derived blocked view accurate.

- [ ] **R04.05 — Claims and leases**
  - Implementation: Atomic select/claim eligible task, role/capability/dependency/policy and budget checks, short BEGIN IMMEDIATE conditional update, one active lease; idempotency key and no LLM inside transaction.
  - Acceptance: 100 parallel claims of same task yield one valid lease; retry same key no duplicate, changed request conflicts.

- [ ] **R04.06 — Fencing tokens**
  - Implementation: Monotonic task fence stored as 64-bit integer, decimal string on wire. Every checkpoint/result/renew verifies session, task/goal/constitution revisions, fence, expiry and policy.
  - Acceptance: Old worker rejected after reclaim, pause or revision change; bigint precision preserved on JSON round trip.

- [ ] **R04.07 — Heartbeat and expiry**
  - Implementation: Server-clock TTL/heartbeat with configurable bounded max window (suggested 120s/30s/15min); sweeper uses same lock order and safe release, no client clock authority.
  - Acceptance: Fake-clock tests renewal, expiry boundary and sweep race; late heartbeat denied; no orphan valid lease.

- [ ] **R04.08 — Persistent checkpoints**
  - Implementation: Append task/fence/sequence checkpoint with summary, work remaining, assumptions, failures, next step, test and artifact refs/hash, validation state. Preserve past attempts; bounded content and no secrets.
  - Acceptance: Crash/reclaim retrieves prior checkpoint with provenance; stale write fails; unverified checkpoint not promoted automatically.

- [ ] **R04.09 — Artifact storage**
  - Implementation: Private local filesystem adapter, scoped upload/finalize, generated keys, size/hash/type checks, quarantine and safe preview, immutable refs; isolated workspace and merge/verifier ADR O10. No agent-supplied trusted paths.
  - Acceptance: Path traversal/cross-scope/hash mismatch rejected; exact bytes retrieved; failed upload cleaned; conflicting edits preserved.

- [ ] **R04.10 — Evidence and independent review**
  - Implementation: Evidence links immutable candidate and criterion revision, trusted verifier/rubric and result; independent reviewer different principal, review accepts/rejects and stale evidence invalidation. Preserve disputed/negative findings.
  - Acceptance: Self-review via different session/model rejected; failed/stale/tampered evidence cannot pass; accepted review advances criterion evidence only.

- [ ] **R04.11 — Task recovery**
  - Implementation: Resume after expiry/release from latest permitted checkpoint, fresh session/fence, verify artifacts and reconcile uncertain side effects, bounded retry and escalation. Pheromone score advisory after hard eligibility.
  - Acceptance: Terminate worker midtask; replacement resumes, no duplicate authoritative result; repeated identical failure produces blocker.

- [ ] **R04.12 — Initial dashboard views**
  - Implementation: Resolve O03 via ADR before scaffold; Vite + TS fixed, UI framework not preselected. Typed client, auth, scoped cache, goal/plan/intent/task Kanban/list and detail, event freshness; accessible list. Host asset packaging fallback.
  - Acceptance: Actual UI shows server projections and version conflicts; no drag-to-Done bypass; keyboard navigation and cross-profile cache clear.

## Milestone exit gate
Concurrent workers claim independent work, planner replacement and alternative proposals preserved, stale writes rejected, fresh worker resumes checkpoint and independent review verifies artifact; initial Vite views usable.
