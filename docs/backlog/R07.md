## Implementation checklist (16 items)

- [ ] **R07.01 — Dashboard Overview**
  - Implementation: Colony state, current goal criteria counts (not fabricated %), active/last-known sessions, runnable/blocked tasks, approvals, budget/unknown usage, last event and prominent pause. Typed read projections and scoped cache.
  - Acceptance: Live data reflects backend, stale/disconnect marked, pause authorized server-side, scope switch clears state.

- [ ] **R07.02 — Goals and criteria**
  - Implementation: List/detail/create/activate/pause/resume/cancel, criterion evidence/candidate hash, blockers, limits, evaluation history and verified completion; human-only changes with expected version.
  - Acceptance: Failed criterion remains visible even all tasks done; unauthorized/stale mutation rejected, CLI parity.

- [ ] **R07.03 — Plans and revisions**
  - Implementation: Inspect strategy, rationale, alternatives, criterion coverage and dependency/intent/task links, diff and history; authorized admit/reject/revise under policy.
  - Acceptance: Historical plan preserved, stale admission conflict refreshes, unaffected tasks visible.

- [ ] **R07.04 — Intents view**
  - Implementation: Filter intent by goal/plan/state/outcome, hypothesis, lineage, evidence, linked tasks and negative results; authorized proposal/admission/cancel where permitted.
  - Acceptance: Refuted/inconclusive outcomes remain visible and not counted as verified goal; lineage links navigate correctly.

- [ ] **R07.05 — Kanban and task list**
  - Implementation: Columns Proposed/Ready/In progress/Blocked/In review/Done plus cancelled filter, goal/plan/role/agent filters and detail drawer. Drag/drop sends transition+expected version, keyboard/list alternative.
  - Acceptance: No direct Done bypass, concurrent conflict refresh, lease ownership and blockers accurate; keyboard workflow usable.

- [ ] **R07.06 — Swarm and sessions**
  - Implementation: Distinguish identity, authorized role, model/provider, session, heartbeat, claim and runner; show current/last known and history; operator revoke or stop managed run.
  - Acceptance: No invented online status; revoked session updates, external run control limitation visible.

- [ ] **R07.07 — Blackboard UI**
  - Implementation: Typed threaded posts, source links, goal/intent/task filters, safe sanitized Markdown, live updates without scroll jump, paginated history.
  - Acceptance: Untrusted text inert; negative result remains searchable, no cross-scope data, reconnect recovers.

- [ ] **R07.08 — Memory Explorer**
  - Implementation: Search scoped claims with verified/proposed/disputed/superseded/rejected/negative states, evidence and checkpoints; show provenance and freshness, pagination and bounded results.
  - Acceptance: Stale/negative/unverified distinguished, source links open authorized artifacts, cache isolated.

- [ ] **R07.09 — Approvals UI**
  - Implementation: Inbox exact action/diff, target, rationale, evidence, expiry, scope and cost; human approve/reject/revoke with reason and expected version; separate approval/effect status.
  - Acceptance: Stale and expired requests fail safely; denial enforced in mock gateway; no optimistic consequential success.

- [ ] **R07.10 — Guardrails UI**
  - Implementation: Edit versioned constitution/policy, capabilities, limits, allowed schedule and runner/workspace restrictions; Observe-only read view, Guided and Autonomous-within-policy presets; hard deny cannot be changed by agent.
  - Acceptance: Policy diff audited, invalid widening rejected, pause persists across reconnect; independent allowed work continues for action denial.

- [ ] **R07.11 — Pulse Dashboard**
  - Implementation: View enabled state, approved schedules, eligible runner, queued/running attempts, blockers, budget and next evaluation; authorized manual trigger/disable/cancel, no arbitrary commands.
  - Acceptance: Disabled scheduler stays disabled across restart, no fake run status, stop and scope checks match CLI.

- [ ] **R07.12 — Activity and audit**
  - Implementation: Chronological typed state transitions with actor, scope, version, correlation, approval and evidence; safe filtered logs and replay; respect retention and privacy.
  - Acceptance: Audit links consequential actions to decision and outcome; secrets/private reasoning absent, cursor gaps resync.

- [ ] **R07.13 — E2E tests**
  - Implementation: Playwright authenticated operator lifecycle, client-only join, Kanban, approvals, guardrails, pause/resume, reconnect, keyboard and stale decisions; close browser while host continues. Mock runners only; test separate static UI fallback if needed.
  - Acceptance: Actual E2E report links SHA, all mandatory PR-19/20 scenarios pass, no frontend bypass.

- [ ] **R07.14 — Installation documentation**
  - Implementation: Quickstart standalone manual install, supported tested OS matrix, local/remote enrollment, auth/TLS, profiles, agent instruction snippet, context/claim/checkpoint, headless/dashboard, upgrade/backup and external limits. No required MCP.
  - Acceptance: Fresh tester follows docs on clean host, two clients share colony, no hidden runtime dependencies; no unsupported claims.

- [ ] **R07.15 — The Immortal Colony demo**
  - Implementation: Synthetic CSV/JSON or seeded bug, deterministic planner/two workers/reviewer; terminate every original session, fail first verification, replan, reject/approve mock intents, pause/resume, browser closure, verified success. Matched-budget no-memory/passive/single baselines; actual research report.
  - Acceptance: Reproducible script/fixtures/hash, evidence and failures; no fabricated metrics; capability assessment for Plane.

- [ ] **R07.16 — Publish alpha**
  - Implementation: Verify R01–R07 gates, actual CI/E2E and research report, signed checksum releases for tested targets, changelog, MIT notices, maintainer security contact/private reporting verified, release approval. No real unattended providers or hosted claims without separate gates.
  - Acceptance: Maintainer approves exact release, download+verify+run smoke, docs reflect actual support and limitations; no SaaS prerequisite.

## Milestone exit gate
Complete functional operator dashboard, headless continuity, reproducible The Immortal Colony demo and tested alpha distribution. R08/R09 annex does not block R07 closure; track separately by original IDs.

## Implementation checklist (12 items)

- [ ] **R08.01 — PostgreSQL adapter**
  - Implementation: Implement same application storage ports/migrations using PostgreSQL transactions and row locks; composite scope FKs, SKIP LOCKED eligible claims, canonical lock order and outbox. No dual writes.
  - Acceptance: SQLite/Postgres contract parity and race suite; restore migration tested, decimal counters preserved.

- [ ] **R08.02 — Row Level Security**
  - Implementation: Forced RLS with non-owner non-BYPASSRLS app role, transaction-local tenant context, deny missing context, migration role separate.
  - Acceptance: Direct SQL/pooled connection cross-tenant reads/writes denied; app auth still enforced.

- [ ] **R08.03 — Multi-tenancy**
  - Implementation: Org membership/roles, colony scope, tenant-aware caches, streams and worker routing; no global unscoped search; onboarding/export/delete.
  - Acceptance: Two orgs isolation tests across API, CLI, SSE, object and search; membership revocation effective.

- [ ] **R08.04 — Object Storage**
  - Implementation: Private S3-compatible adapter, scoped presigned upload, finalize hash/size/type, quarantine, bounded expiry and deletion/retention; no public default.
  - Acceptance: Cross-tenant URL and bad hash denied; signed link expires; restore verifies artifact bytes.

- [ ] **R08.05 — Quotas and metering**
  - Implementation: Atomic hard counters and idempotent usage ledger, per-org rate/concurrency/storage caps, fairness and backpressure. Distinguish BYO provider cost unknown from managed spend.
  - Acceptance: Concurrent cap enforcement and duplicate-event tests; one tenant cannot starve another.

- [ ] **R08.06 — Billing**
  - Implementation: Select billing adapter and plan entitlements via approved O11 ADR; signed webhooks, dedup/replay protection, reconciliation and compensating entries; no card storage or invented pricing.
  - Acceptance: Mock billing lifecycle and webhook tampering tests, invoice quantities traceable to ledger; approval before paid integration.

- [ ] **R08.07 — Cloud authentication**
  - Implementation: Choose approved identity provider, secure browser sessions/CSRF, agent scoped tokens and rotation, org invitations/revocation, remote TLS and audit.
  - Acceptance: Cross-org/CSRF/session fixation/revocation tests; no plaintext secrets; no client policy authority.

- [ ] **R08.08 — Horizontal API**
  - Implementation: Stateless API replicas behind load balancer, shared authoritative DB, pool limits, readiness/drain, compatible migrations and scoped SSE gateway when measured necessary.
  - Acceptance: Multi-replica claim/idempotency tests, rolling upgrade and reconnect without lost authoritative state.

- [ ] **R08.09 — Distributed workers**
  - Implementation: Durable outbox/reconciliation claims, leases/dedup, bounded retry/DLQ, fair tenant routing; external side effect uncertainty reconciled; broker only after measured need.
  - Acceptance: Crash/replay across replicas one effective projection/action; no duplicate budget settlement.

- [ ] **R08.10 — Monitoring**
  - Implementation: OpenTelemetry trace/metrics/logs, correlation, p95/lock waits/outbox lag/SSE/quotas/restore alerts, bounded labels and secret redaction; incident runbooks.
  - Acceptance: Inject known errors/lag and verify alerts; trace links command→event, no secrets/high-cardinality identifiers in metrics.

- [ ] **R08.11 — Load tests**
  - Implementation: Synthetic multi-tenant workloads, hot colony and SSE, claims/review/large payload mix; compare planned targets 100 org/100 active/20 commands/s then beta goals, measure latency/cost/limits; no invented capacity.
  - Acceptance: Report reproducible scripts/environment/distributions, p95/errors and bottlenecks; release gate agreed on measured evidence.

- [ ] **R08.12 — Backup and disaster recovery**
  - Implementation: Managed Postgres PITR, encrypted object/DB backup, retention/deletion, isolated restore drills, schema compatibility, RPO/RTO targets verified before SLA.
  - Acceptance: Restore exact state/evidence and scoped access; record actual RPO/RTO, failure recovery and operator-approved beta readiness.

## Milestone exit gate
Hosted beta separately approved after parity, RLS, abuse, load and restore checks; pricing/provider pending O11; no R07 release dependency.

## Implementation checklist (6 items)

- [ ] **R09.01 — Collective intelligence benchmarks**
  - Implementation: Predeclare hypotheses, synthetic fixtures, budgets, model/runner versions, seeds and independent verifier; compare single agent, supervisor, passive board and proactive structured memory. Publish actual metrics and negative results.
  - Acceptance: Reproduction from committed config/hashes, distributions and limitations; no consciousness/guaranteed success claim.

- [ ] **R09.02 — Swarm topology comparisons**
  - Implementation: Compare generalists, replaceable Planner+Workers+Reviewer and alternative planner proposals under matched resources; vary scheduling/role assignment only; measure duplication, overhead, quality and intervention.
  - Acceptance: Controlled repeated runs with resource parity and independent checks; record confounders and no winner if unsupported.

- [ ] **R09.03 — Generational continuity experiments**
  - Implementation: Terminate all sessions at declared boundaries, preserve only authorized durable state; restart different identities/models, compare no-memory and passive controls, include rejected evidence and stale checkpoint cases.
  - Acceptance: Measure recovery latency, context fidelity, accepted progress and repeated failures, document actual evidence and stop conditions.

- [ ] **R09.04 — Transfer capabilities to Plane**
  - Implementation: Maintain maturity register, sanitized fixtures, versioned contracts/ADRs and optional pure TS modules. Plane intended functional superset with humans/projects; independent architecture, permissions and scale review, no mandatory DB/deploy dependency.
  - Acceptance: Transfer packet and adoption decision per capability, no private Plane code/data or claims of shipped integration.

- [ ] **R09.05 — Advanced Exploration Graph**
  - Implementation: Build optional graph view of goal→plan/intent/task→evidence/criterion and revisions, filters and provenance; relational storage, accessible list alternative, virtualization and scoped API.
  - Acceptance: Graph navigates refuted and accepted paths accurately, no invented causal edges, performance and keyboard tests.

- [ ] **R09.06 — Evaluate federation**
  - Implementation: Research RFC only: explicit colony trust, tenant isolation, revocation, identity, conflict and replication/partition semantics, opt-in data boundaries; no automatic cross-colony propagation or agent authority escalation.
  - Acceptance: Threat model, alternatives and controlled synthetic experiments; proceed only after separate approval and measured benefit.

## Milestone exit gate
Reproducible evidence and separate adoption review; graph/federation optional research not alpha requirements.
