# Contributing

ANTS is pre-alpha. Discuss significant changes in an issue/RFC before implementation. Claim a scoped task; state dependencies, acceptance criteria and planned files. Avoid duplicate work. Use a branch, focused commits and PR with tests/docs; report AI-assisted changes and verify them yourself. Do not submit secrets, personal data, unlicensed code or unsafe external tool actions. Maintainers review evidence, not just generated output. A failed attempt with reproducible evidence can be useful. English is preferred for public technical contributions.

When code exists, CI must pass and independent review is required. Current documentation changes should preserve cross-links and label proposals vs shipped functionality. MIT contributions by default, subject to license and contributor rights. No CLA proposed initially.

Read [handoff](docs/24-handoff.md) and [requirements](docs/23-requirements.md) before proposing work. Use R01–R09 and PR requirement IDs, record acceptance/negative tests, dependency boundaries and checkpoint. Update affected specs/ADRs/schema examples when changing behavior. Current next milestone R01; no runnable code yet. Do not publish claims of measured scale or successful tests without evidence. Preserve private Plane boundaries and third-party licensing.

## Mandatory implementation contract

Follow [IC v1.0](docs/25-implementation-contract.md), including Definition of Ready/Done, scoped ownership, exact test evidence, independent review and authorized integration. Use [backlog](docs/backlog/README.md) IDs and [per-item checkpoint](docs/implementation/checkpoint-template.md). No self-approval or checked item from unverified code. Default branch/PR, direct main only with explicit scope authorization. These rules apply equally to human and AI contributors.
